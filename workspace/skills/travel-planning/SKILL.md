# 旅行规划

先从请求中提取出发地、目的地、当地日期、人数与儿童年龄、预算口径、交通方式和行动限制。缺少日期时可以研究区域和候选景点，但不能给出已核实的房价或库存；只追问影响当前决策的缺项。

## 按可用能力取证

规划时用 `search_capabilities` 搜索地图、攻略、酒店、门票和浏览器能力，按返回的完整 code 选择工具。MCP code 形如 `mcp.<server>.<tool>`；这个模式不是可直接执行的工具名。读取实际参数 schema，不从服务名猜测操作。执行节点若没有所需工具，将缺口交回规划器，不假装已查过。

- 小红书：有可用连接及必要登录时，搜索近期笔记、读取原文和时间，用于体验、排队与选区线索。未登录不阻塞整个规划，可继续公开网页检索并说明来源；用户指定必须参考小红书时，明确该部分尚未完成。笔记热度不能证明营业时间、价格或通行条件。
- 高德或百度地图：需要对应 API key 和已启用的连接。先确认城市、同名地点及实际入口，再查所选出行方式的路线；保留提供方、查询时间和适用出发时间。同一路段尽量使用同一提供方的 POI，不能直接混用不同坐标系的原始经纬度。没有路线结果时标为估算，不把直线距离当通行时间。
- 途牛酒店或门票：只选择目录中真实存在的查询能力。酒店匹配入住/离店日期、房间数、入住人数、房型与餐食；门票匹配游玩日期、场次、适用人群和包含项目。结果缺项时保留缺项，不补造库存。
- 携程或去哪儿：如用户指定这些平台，或当前结构化查询无法满足需求，可通过已发现的浏览器能力查看公开或已授权会话中的页面。记录实际平台、链接和筛选条件；浏览器页面不是途牛报价。登录或访问受限时说明受限处，不宣称完成查询。

## 组合可执行方案

按地理区域组织每天的游览顺序，用路线结果检验来回交通、入场截止时间和预约场次，留出用餐、排队和换乘余量。攻略中的建议与景区公告冲突时，以适用旅行日期的官方公告为准；保留冲突来源，避免用旧笔记安排已关闭的活动。

住宿和门票比较必须使用相同条件。列出币种、计价单位、数量、含税费总价、餐食或附加费用、取消截止时间及其时区、退改费用、是否有库存和查询时间。区分每晚价与全程价、每人价与合计；无法核实税费或取消规则的报价不能描述为确定总价或免费取消。查询时有库存也不等于已预订。

交付按日行程、可比候选及预算拆分，关键安排附来源链接和适用日期，区分已查证、估算与待确认。预算不全时只给已知小计。规划不授权下单、付款、发帖或联系商家；已有用户明确授权的后续动作按其范围执行。

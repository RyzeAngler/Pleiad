# 数据审计

先检查输入结构和数据质量，再进行分析。优先使用 Tool 返回的确定性结果，不要用猜测替代缺失数据。

审计 CSV 时，选择 `data.tool.csv_profile`，传入工作区内的 `path`。文件需为 UTF-8（可带 BOM）、逗号分隔且表头非空不重复；支持引号、字段内逗号和换行。工具只读文件，不修改数据。

- `row_count` 是数据记录数，不包含表头；空白物理行会被 CSV 解析器跳过。
- `empty_count` 只统计空字符串。空格、`NULL`、`N/A` 等文本保留原样；不要擅自把它们当成缺失值。
- `samples` 是每列最先出现的非空值，不是随机或代表性样本。`sample_size` 默认 3，最多 5；每个样例最多保留 200 字符，不能据此判断完整内容相同。
- 只有显式列入 `numeric_columns` 的列才提供数值摘要。先依据用户目标或数据定义选择列，编号、邮编等保持文本；未选择时 `numeric` 为 `null`，不会自动猜测或覆盖类型。
- 数值摘要排除空值，分别报告 `valid_count` 和 `invalid_count`；非数字及超出有限浮点数范围的值计入后者。最小值、最大值和均值以浮点数返回，不作为精确财务计算结果；没有有效数值时三者为 `null`。
- 表头、记录列数或路径校验失败时，报告工具错误并核实输入，不把失败解释为零行或没有问题。

例如：`{"path":"scratch/orders.csv","numeric_columns":["quantity","amount"],"sample_size":3}`。先对照行数、空值和无效数值数量，再引用具体列和样例说明问题。普通文本文件可使用 `example.tool.text_statistics` 获取基础统计。

输出应说明发现、证据、影响和建议，并保持结构与节点输出模式一致。

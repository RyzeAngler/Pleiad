## 1. 必须遵守的产品决定

**新增持续协作形式，与现有 `Subagent / SubagentGroup` 并存。禁止删除、重命名、替换现有公共 API，或改变其父 Run 作用域、预算、取消、等待和恢复语义。现有调用方不需要迁移。**

两种形式解决不同问题：

| 形式 | 生命周期 | 使用场景 |
| --- | --- | --- |
| 现有 SubagentGroup | 父 Run 范围内的独立子调用，随所属作用域结算 | 委派一个任务并收回结果、Graph 节点内委派、受父 Run 管理的并行工作 |
| 新增协作形式 | 宿主拥有协作作用域；子 Agent 保留稳定身份与独立 Session，可执行多轮任务 | 动态分工、发送补充信息、完成后追加任务、保留上下文继续协作 |

现有 SDK 子调用本身可以执行多步工具循环；Canvas 当前 `max_model_steps=1` 是调用方限制，不是旧 SDK 机制的定义。不能以“旧方式只会回复一次”为理由将其废弃。

AGENTS.md 中删除被替代接口的规则不适用于这两种不同用途的协作形式。用户已明确要求并存。可复用通用基础组件，但不能为了代码复用改变旧接口行为，也不要建立兼容别名或把旧实现偷偷转发到新生命周期。

## 2. 交付目标

在 SDK 中实现一个独立、可公开调用的持续协作模块，复用现有 Agent、Session、Runner、RunHandle、ToolRuntime、预算与权限机制。模块名和类型名由源码设计确定，任务书不强制命名。

交付完整的 Python 公共 API、可选模型工具包装、类型化输入/输出及事件、持久状态和恢复契约、示例、行为测试和架构说明。SDK 保持 provider-neutral；不引入 Canvas 数据库、Execution DTO、FastAPI 或商品业务。

本任务先完成本地源码实现和交付，随后由 Canvas 安装本地源码联调。联合验收通过后统一确定版本并发布；此任务不提前上传 PyPI、推送代码或修改外部服务。

## 3. 必须支持的操作语义

以下为语义要求，实际函数名可按 SDK 命名规范确定。Python API 与模型工具应走同一条运行路径。

| 操作 | 要求 |
| --- | --- |
| spawn | 从宿主允许的 Agent/能力绑定创建独立子身份与 Session，提交初始任务；及时返回受理身份，不能伪装为任务已完成 |
| send_message | 给已有 Agent 投递消息，空闲 Agent 不因纯消息自动开始新 Run；活跃 Agent 在安全边界消费；返回可追踪的消息回执 |
| followup | 给已有子 Agent 安排新工作；空闲/已完成时在原 Session 创建新 Run；运行中如何追加或排队必须有明确契约，不能并发写同一 Session |
| interrupt | 请求停止指定活跃 Run，等待可核实的结算；保留 Agent 身份、Session 历史和已有结果，后续仍可 follow-up |
| wait | 等待指定 Agent 集合的新增事件，支持 wait-any、游标和有界等待；返回事件/状态而非重复注入全部历史 |
| list/status | 查看授权作用域内的 Agent、父子关系、当前 Run 和状态；从持久事实与运行状态投影，不靠模型自行描述 |
| close | 明确关闭 Agent 或协作作用域，结算拥有的任务并释放资源；与 interrupt 和删除历史分开 |

子 Agent 在受限工具集合内可多轮调用工具。初始任务与后续消息需支持文本和 SDK 已有图片引用，不能把多模态输入再次降格成仅含图片 ID 的字符串。

默认按任务选择上下文。需要继承父上下文时，明确快照边界、来源、权限和预算，不共享可变消息列表；首版不要求实现任意历史分叉。模型可决定任务与允许的能力模板，不能自行创建任意客户端、凭据或工具实现。

## 4. 身份、状态与所有权

实施前在设计文档中确定并测试以下区分：

- Agent 身份与 Session 在 follow-up 时保持稳定；每轮工作有独立 invocation/Run 身份。
- 任务/消息请求具有稳定幂等身份。同身份同载荷返回原受理结果；异载荷明确冲突。
- 已完成 Run 的终态不可改回 running；新任务创建新 Run，不覆盖旧结果。
- Agent 是否开放、单轮是否运行、消息是否已接收/已消费是不同事实。
- 协作作用域由宿主显式创建和关闭，可以跨多个主 Agent Run；主 Run 正常结束不隐式删除子 Session。
- 主 Run 结束或取消时，其尚未结算工作和预算如何处理必须显式定义。默认停止并结算该 Run 拥有的在途工作，Agent 身份仍可保留；不得让子任务无授权地在后台继续。
- 同一 Session 最多一个活跃 writer。两个并发 follow-up、follow-up 与 interrupt 的竞争有可验证结果。
- 一个 Agent 失败应形成自身失败事实，不能无意取消同级无关 Agent；作用域级关闭则须收敛全部资源。

沿用结构化并发和明确资源拥有者，不用无主 asyncio task，也不复制 Runner 的模型执行循环。SDK 提供通用运行记录，宿主继续拥有其产品作业和 parent_execution_id；SDK Agent 身份不能替代产品 Execution。

## 5. 预算、权限和准入

每轮请求绑定当轮有效的模型配置、工具允许集合、grants、期限和预算。follow-up 不继承已结束 Run 的过期期限，也不能复用已结算额度；宿主为新工作提供新授权。Agent 上下文可持续，不代表权限永久有效。

支持协作作用域的并发上限与有界待执行队列或明确的超限拒绝策略。若允许递归 spawn，限制应覆盖整棵树；若首版只支持一层，在契约中明确拒绝更深委派。不要在 SDK 中写死 Canvas 的 3 个并发或一层策略。

复用现有预算账本，明确并发预留、使用量归属、取消结算及重试去重。没有确认未使用的额度不能返还。图片收费操作仍归宿主的持久 operation 账本，不从文本 token 用量推导图片费用。

图片通过当前 Session/Run 的 Resolver 重新授权，持续 Agent 不能靠旧消息绕过素材权限变化。SDK 事件不泄露凭据、临时认证 URL 或原始模型推理。

## 6. 持久化、事件与恢复

使用已有 SessionStore/Runner 持久原语保存会话与 Run；新增协作关系和消息状态只保存必要事实。若需要额外存储接口，先证明现有存储无法表达，再提供与当前 SDK 一致的默认后端。禁止以临时 Python 字典充当重启后仍可靠的全部事实源。

公共事件至少能表达：创建受理、排队/开始、消息接收与消费、公开输出/工具活动、结果就绪、失败、中断请求与结算、关闭。事件携带稳定身份、来源 Agent、目标 Agent/Run 和可恢复游标。

公开事件可重放，消费者按稳定事件 ID 去重；明确 at-least-once 投递与幂等消费边界。wait 超时是暂未出现新事件，不是失败、完成或取消。结果应可按引用读取，避免每次 wait 返回全量会话。

进程重启后恢复稳定 Agent/Session 关系、已受理消息和已提交终态。进行中的调用只有存在合法 SDK 恢复点时才恢复，否则明确标记中断或结果待核实，不能把旧内存任务当成仍运行，也不能自动重提未知收费操作。

## 7. 最小完整验收场景

1. 现有 SubagentGroup 的同步/异步委派、暂停恢复、预算、父取消及 Graph/Handoff 组合回归保持通过；旧调用方无需改代码。
2. 一个主 Agent 动态创建两个子 Agent；独立 Session，实际并行，返回受控摘要。
3. 子 Agent 使用多步工具完成任务，图片块经过真实 Runner/Resolver 到达外部模型传输边界。
4. 活跃子 Agent 收到补充信息；能区分已接收与已消费；消息按稳定顺序在安全边界生效。
5. 子 Agent 完成后追加任务，保持原 Session 上下文、新建 Run；首轮结果仍可查询。
6. interrupt 只停止目标在途 Run，保留上下文；随后 follow-up 正常继续。
7. 同一请求重送不重复创建、运行或消费；同 ID 不同载荷冲突。
8. 并发 follow-up、interrupt、close 竞争不出现双 writer、错误终态或失去所有权的后台任务。
9. wait-any 在新增事件到来时返回；重复读取不产生重复计费/结果注入；超时不改变任务状态。
10. 一项失败不导致无关兄弟任务消失；并发、递归、队列及预算限制在真实调度路径生效。
11. 重启后可恢复历史、原回执及消息事实；未知在途结果明确展示，不自动重提外部操作。
12. 权限与图片授权保持有效；不能跨协作作用域读取或控制不属于自己的 Agent。
13. 关闭协作作用域后全部拥有的模型流、工具、task 和客户端资源完成清理。

遵循 AGENTS.md 与 testing-python skill。测试使用真实 SDK 组件，仅在外部模型/网络等边界注入确定响应；并发场景使用屏障或故障注入，不靠固定 sleep。先跑聚焦测试，再跑 SDK Ruff、mypy、完整确定性测试；涉及公共共享机制时跑 Weave 回归与导入边界，涉及发行内容时跑打包验证。真实供应商测试单独记录。
